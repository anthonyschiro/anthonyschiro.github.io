Saving as a set of small contracts

SaveSystem is a static class that writes one JSON file per slot to Application.persistentDataPath using JsonUtility. Each component exposes Save(ref data) and Load(data), and the save system just aggregates them: player, fuel tube, game manager, world items, machines, platforms, quests and navigation. Tracking down bugs

Saved platforms were loading tiny and wrongly rotated. The cause was GridSystem instantiating a different prefab from the one used in the scene, so I pointed it at the right prefab and made the placement ghost match the real placement. Another bug, in mission generation, traced back to asset configuration flags and the order in which ProgressData was reset.

Wilba Metrobus App

A mobile-first web app that lets rural passengers pool onto bus trips, where the fare drops as more people commit.

<img src="media/wilba-app1.mp4" alt="…">

The pooling idea

Passengers commit a maximum price they’re willing to pay. Each segment of a line has a capacity of 10, and its cost is split among the people riding that segment, so the price falls as more people join. A trip is confirmed once the price reaches what passengers have committed. A passenger can reopen a pooled trip later and change their maximum.

Data model

MongoDB holds stops, lines and trips. Lines are made of segments (from, to, duration_minutes), and every trip runs the full line, so pricing can be worked out per segment. A trip carries its passengers, each with a start stop, end stop and current price. Confirmed or pooling is derived from that data rather than stored as a status field, which keeps the search page and booked-trips page consistent with each other.

Front end

React with Vite, built mobile-first from our Figma mockups, using React Router for the Trips and Search pages. Search results look different for confirmed and pooling trips, and both lead to the pooling page. After client feedback on our documentation, we added PWA features for a more native feel.

Working with a client

We presented the system architecture to the client using front-end/API diagrams and DFD and C4 diagrams. Our team had gaps in React, Node and Express, so we worked through Full Stack Open together to close them.
